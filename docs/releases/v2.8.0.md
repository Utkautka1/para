# Release Specification & Technical Comparison: v2.8.0 vs v2.7.0

## Executive Summary

**Release v2.8.0** represents a transformative enterprise engineering and production readiness milestone for the **Para** distributed academic ecosystem.

While **v2.7.0** achieved 100% codebase refactoring to micro-functions ($\le 25$ lines), unified 3-part Russian docstrings, and dual-endpoint timetable failover, **v2.8.0** implements the complete 21-point engineering audit across four critical operational dimensions:
1. **Security & Supply Chain Hardening**: Zero-trust pre-commit framework (10 hooks), detect-secrets baseline, non-root `appuser` (UID 1000) execution across all four microservice Dockerfiles, PyPA vulnerability auditing (`pip-audit`), and automated Trivy container vulnerability gates in GitHub Actions.
2. **Production Observability & Tracing**: Native Prometheus metrics engine exposing process memory, CPU, HTTP latency histograms, and queue depth via `GET /metrics`. Distributed `trace_id` logging format `[trace_id: ...] [thread: ...]` with `X-Request-ID` propagation.
3. **Architectural Modularity & Developer Experience**: Decomposition of the 378-line solver monolith into `services/solver/`, structured domain configuration models (`core/config_models.py`), automated developer setup scripts (`scripts/dev_setup.sh`), CODEOWNERS, PR templates, and static OpenAPI schema export.
4. **Multimodal AI Resilience & Data Governance**: Input sanitization neutralizing prompt injection / jailbreak vectors, stateful async Circuit Breaker (`CLOSED`, `OPEN`, `HALF_OPEN`) with exponential backoff and jitter, strict MyPy type checking, expanded test suite (**629 passing tests**, up from 594), and comprehensive GDPR / 152-ФЗ compliance documentation in `docs/PRIVACY.md`.

## 2. Component-by-Component Comparison: v2.7.0 vs v2.8.0

### 2.1. Container Hardening & Docker Delivery

* **In v2.7.0:**
  * Dockerfiles executed all processes under default Linux user `root`.
  * Container file writes could create root-owned files on mounted host volumes.
  * No container vulnerability gate in CI.
* **In v2.8.0:**
  * Added unprivileged system group `appgroup` (GID 1000) and user `appuser` (UID 1000) in all four Dockerfiles (`api.dockerfile`, `bot.dockerfile`, `worker.dockerfile`, `solver.dockerfile`).
  * Enforced ownership on `/app/data` and `/app/logs` matching Linux host UID/GID.
  * Integrated automated Trivy scanner in CI (`aquasecurity/trivy-action`) blocking CRITICAL CVEs.

### 2.2. Observability, Metrics & Distributed Tracing

* **In v2.7.0:**
  * Telemetry was restricted to text log files in `logs/`.
  * Correlating logs across microservices for a specific student request was impossible without manual timestamp matching.
* **In v2.8.0:**
  * Created `core/metrics.py` and `api/router/metrics.py` exposing standardized Prometheus metrics at `GET /metrics`.
  * Added `contextvars` `trace_id` logging format `[trace_id: ...] [thread: ...]` in `core/logger.py`.
  * Added `X-Request-ID` middleware in `api/__init__.py` propagating correlation tokens between callers and internal services.

### 2.3. Solver Architecture Decomposition

* **In v2.7.0:**
  * `solver.py` was a 378-line monolith containing document parsing, PDF extraction, Telegram bot communication, DeepSeek invocation, and queue polling.
* **In v2.8.0:**
  * Decomposed `solver.py` into a specialized package `services/solver/`:
    - `payload_extractor.py`: Safe download, Docx/PDF/Code extraction with size bounds.
    - `telegram_reporter.py`: Delivery of solution documents and error notifications.
    - `task_processor.py`: Parallel worker loop executing under concurrency semaphores with atomic ACK/NACK.
  * Reduced `solver.py` entrypoint to a lean 58-line lifecycle orchestrator.

### 2.4. Domain Configuration Models

* **In v2.7.0:**
  * `config.py` contained over 70 flat global variables. Domain concepts were only separated by comments.
* **In v2.8.0:**
  * Created `core/config_models.py` with typed, frozen domain dataclasses (`TelegramConfig`, `ScheduleConfig`, `CampusConfig`, `RedisConfig`, `YandexConfig`, `ApiConfig`, `AiSolverConfig`, `WhisperConfig`, `NotificationConfig`).
  * Refactored `config.py` to instantiate domain objects while preserving 100% backward-compatible constant exports.

### 2.5. AI Safety & Fault-Tolerant Resilience

* **In v2.7.0:**
  * DeepSeek API calls had no protection against prompt injection, tag escape (`</учебное_задание>`), or external network outages.
* **In v2.8.0:**
  * Created `core/prompt_sanitizer.py` implementing Unicode normalization, zero-width / control character removal, delimiter escaping, and regex-based injection detection.
  * Created `core/circuit_breaker.py` with finite states (`CLOSED`, `OPEN`, `HALF_OPEN`), fast fail protection, and exponential retry backoff with jitter.
  * Integrated both defenses into `integrations/deepseek.py`.

### 2.6. Privacy & Legal Governance

* **In v2.7.0:**
  * Privacy documentation did not specify ephemeral storage mechanisms or structured erasure workflows.
* **In v2.8.0:**
  * Expanded `docs/PRIVACY.md` detailing voice audio handling on `/dev/shm` RAM-disk with guaranteed post-transcription unlinking, Russian Federal Law No. 152-FZ data localization compliance, and a formal 5-step Right to Erasure / Right to be Forgotten procedure.
